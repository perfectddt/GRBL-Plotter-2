## 1. 目的与背景

- 痛点：停止/暂停后笔不离纸（长笔画中断后笔尖仍压纸，拖纸风险）。绕过 planner 的实时抬笔入口需要 BtWriter 1.3a.20221114 定制固件的协议确认。
- 本会话路线：不依赖厂家，**被动嗅探原版奎享雕刻**与机器之间的串口流量——厂商软件执行"暂停/停止"的一瞬间发了什么字节，就是最终答案。
- 分工约定：字形扩容/单线字体在另一对话框进行；本会话不修改仓库代码（本交接文档除外，未提交）。

## 2. 已确认事实（按证据强度排序）

1. **固件协议网上零公开资料**。精确串 `1.3a.20221114`、`[OPT:MPHB]` 搜索零命中；GitHub/Gitee 无该固件逆向项目；CNCDraw 项目只有上位机移植（其 `K_AT` 枚举全网无实现）。
2. **34 项 `$` 设置恰好 = 标准 Grbl 1.1 全集**（`artifacts/stage1/controller-snapshot.json` 逐项核对，一项不多不少）→ 全部定制编译在固件里，`$` 层面无暂停/笔控钩子可调。
3. **厂商上位机自己就是 Z 轴笔控驱动本机型**：安装目录 `default.properties` → `fixed_machine_type=grb1`、`grbl_type=Stepper`、`zOn=5`、`zOff=0`，与实机 R 系列测试（绝对 Z0/Z5 走规划队列）一致。
4. 厂商软件栈：`奎享雕刻.exe`（自包含 JVM，无 javaw 子进程）+ `kenjoycncc.dll` 原生串口库 + Launcher_guard 加密 core；GUI 为 Java Swing（Windows UIA 不可见，GUI 自动化只能截图+坐标）。

**成功的部分**：

**失败的部分与根因分析**：

- "frida 注入致崩"证据不足（崩溃进程从未被注入）；0xc0000409 也可能是厂商自身缺陷。是否可复现、是否与 frida 相关，**待判定**。
