### 关键结论

1. **软件暂停/停止都先等 IDLE**：`PauseStreaming` 置 `isStreamingRequestPause` → `PreProcessStreaming` 立即 return → 等在飞的行跑完 → `StreamingIDLE()` 才切 pause。**停止点由最后一行已排出的代码决定，不由笔画边界决定**。缓冲 127B、一笔约 40B（10+20+10）≈ 3 笔在飞 → 可能停在绘制行末尾，笔仍 Z5 下压。
2. **六种停法都不抬笔** → 停在绘制行末尾时笔尖压纸静止（渗墨/压痕），续画留接头。
3. 「进料保持 `!` + 恢复 `~`」**唯一位置连续**：实时字节、不等 IDLE、保留规划缓冲、恢复不重发模态、不做位置恢复 → 对连续笔控最干净，但笔仍压着。
4. `PauseStreaming` 恢复分支：`posPause ≠ posWork` 时走 `G90 G0 X.. Y..` → `G4 P0.5` → `G0 Z..` → 重发 `parserStateGC`。**第一条 `G0` 早于恢复 Z** → 带笔横移（拖线）风险；日志出现 `[Restore Position]` 即走了该分支。
5. `flowControlEnable` 默认 **true**、`flowControlText` 默认 **`M5; M9`**，暂停/停止后由主定时器延迟执行一次（`MainForm.cs:613-619`）。对 Z 笔机器无害，但是**唯一能挂「暂停自动抬笔」的钩子**（对 `!` 无效）。
6. 软复位 Ctrl-X 无减速；`StateReset()` 使 `grblStateNow=unknown`、`mParserState.Reset()`；本机 `$20/$21/$22=0` 无兜底 → 不当暂停用。
7. 停止 ■ 与软复位后**不可续画**，都不回原点（与 20:27 端到端实测后手动回位一致）。
