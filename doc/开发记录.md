### 本阶段修复

1. 用户级 NuGet.Config 原先没有软件源，恢复失败。新增仓库根目录 [NuGet.Config](../NuGet.Config)，限定官方 nuget.org 源，没有改动用户全局配置。
2. 首次构建报 MSB3644，缺少 .NET 4.8 参考程序集；补齐参考程序集后又报 MSB3086，缺少 `al.exe`。从 Microsoft 官方地址下载 Developer Pack，Authenticode 签名为 Valid、签名者 Microsoft Corporation，并安装成功。最终构建使用完整 SDK，不依赖临时参考程序集路径。
3. Debug 的旧式构建后 FxCop 检查报 CA0001。将 csproj 的 `RunCodeAnalysis` 改为 false，保留 WarningLevel 4；未关闭 C# 编译警告。后续若需要静态分析，应单独引入并验证兼容的分析器，不能将本次构建说成已经通过现代静态分析。
4. 新增 `--offline` 参数用于基线检查：拦截主／第二 GRBL 控制器的自动和手动连接，跳过第三串口、DIY 控制板及工艺自动化的启动入口，跳过启动更新检查；离线数据和日志使用当前输出目录。
5. 文件输入参数过滤掉 `--offline`，避免原有 `LoadFiles` 将其当作文件名或集合名称。保留命令行输入 SVG 的能力。
6. 新增 [构建脚本](../scripts/build.ps1) 和 [资源／依赖核对脚本](../scripts/verify-baseline.ps1)，构建产物、日志、下载文件和配置副本放入被 Git 忽略的 `artifacts/`。

离线参数用于本阶段的检查，不代表完整的应用隔离：设置仍由 .NET 保存到用户配置目录；不要在此模式中手动打开其他辅助设备入口或运行自定义脚本。正式连接机器人使用经阶段 1 核对的配置。

当前修复：移除 App.config 中 PerMonitorV2 的显式启用，让旧界面采用 Windows 兼容缩放。没有修改用户 Windows 显示缩放或系统字体。该模式下运行时 DeviceDpi 为 96、UI 字体 9 pt、设计客户区 1264 × 631，控件和文字保持相同比例。配置背景参考 [Microsoft 的 WinForms 高 DPI 说明](https://learn.microsoft.com/zh-cn/dotnet/desktop/winforms/high-dpi-support-in-windows-forms)。

#### 核对结论：界面上有 6 种不同的「停」

| 入口 | 位置 | 实际动作 | 层次 |
|---|---|---|---|
| 绿色 ▶ / ⏸（同一按钮） | 左栏「G 代码流」 | `PauseStreaming()` | 软件流控 |
| 红色 ■ | 左栏「G 代码流」 | `StopStreaming()` → 清空两个缓冲 | 软件流控 |
| 「进料保持」 | 左栏「流量控制」 | 实时字节 `!`(0x21) | 固件实时 |
| 「恢复」 | 左栏「流量控制」 | 实时字节 `~`(0x7E) | 固件实时 |
| 「重置」 | 左栏「流量控制」 | Ctrl-X(0x18) 软复位 | 固件复位 |
| 「紧急报警」 | 左栏「流量控制」 | `$X`（只解报警，不产生运动） | 固件 |

（另「门」发 0x84，本机未接线，不使用。）

#### 关键发现

1. **软件暂停/停止都「先等 IDLE」再停**（`PauseStreaming` 置 `isStreamingRequestPause` → `PreProcessStreaming` 立即 return → 等在飞的行跑完 → `StreamingIDLE()` 才切 pause）。因此**停止点由「最后一行已排出的代码」决定，不由笔画边界决定**。本机缓冲 127 字节、一笔约 40 字节（落笔 10 + 绘制 ~20 + 抬笔 10），约 3 笔在飞 → **可能停在绘制行末尾，笔仍处 Z5 下压**。
2. **六种停法没有一种会抬笔** → 停在绘制行末尾时笔尖压在纸上静止，渗墨/压痕；续画会留接头。
3. 「进料保持 `!` + 恢复 `~`」是**唯一位置连续**的暂停：实时字节、不等 IDLE、保留规划缓冲、恢复时不重发模态、不做位置恢复 → 对连续笔控最干净，但笔仍压着（短停几秒影响最小）。
4. `PauseStreaming` 恢复分支：若 `posPause ≠ posWork`（暂停期间被手动移动过）先 `G90 G0 X.. Y..` → `G4 P0.5` → `G0 Z..` 再重发 `parserStateGC`。**第一条是 `G0` 快速移动且早于恢复 Z** → 带笔横移（拖线）风险。日志出现 `[Restore Position]` 即表示走了该分支。
5. `flowControlEnable` 默认 `true`、`flowControlText` 默认 `M5; M9`：暂停/停止后由主定时器延迟执行一次（`MainForm.cs:613-619`）。对 Z 笔机器无害，但**这是唯一能挂「暂停自动抬笔」的钩子**（对 `!` 进料保持无效）。
6. 软复位 Ctrl-X 无减速过程，`StateReset()` 把 `grblStateNow=unknown`、`mParserState.Reset()`；本机 `$20/$21/$22=0` 无任何兜底 → 不当暂停用。
7. 停止 ■ 与软复位后**不可续画**，且都不回原点，与 20:27 端到端实测后由操作者手动回位一致。
