# 写字编辑器与预览行数一致性修复（2026-10-11）

根因是 WinForms 多行 TextBox 的 Windows EDIT 控件与排版服务对混合换行字符的解释不同，不是用户视觉上多输入了空行。实际上次设置中的两句文字分隔字符为 `CR LF LF`。Windows 原生 `EM_GETLINECOUNT` 返回两行，但 `TextBox.Lines` 和排版服务读取该文本返回三行。

在真实 Windows 控件上复现：`A\r\n\nB` 原生显示两行、托管读取三行；`A\r\r\nB` 同样两行/三行；正常的 `A\r\n\r\nB` 两边均为三行。

现在在恢复设置、打开项目、编辑/粘贴、生成和保存的 UI 边界统一为 CRLF。CRLF 后附带的孤立 LF 和 CRCRLF 按原生编辑器已显示的单次换行处理。正常 CRLFCRLF 和纯 LF LF 的有意空行保留。关闭编辑器视觉自动折行，启用水平和垂直滚动，页面自动换行仍由排版设置控制。

使用紧凑标点真实字体、字号6mm、字距1mm、原两句文字测量生成笔迹边界：

| 行间隙设置 | 修复前混合换行 | 修复后 |
| --- | --- | --- |
| 0mm | 6mm | 0mm（浮点误差约 2e-15） |
| 2mm | 10mm | 2mm |

验证脚本 `scripts/test-writing-editor-newlines.ps1` 覆盖原生行数、七种换行输入、规范化幂等性和真实字体的边界间隙。`scripts/WritingEditorUiTests.cs` 对实际 MachineSetupForm 验证编辑赋值、旧状态恢复、规范化保存及空行保留。Release 构建输出为 `artifacts/newline-fix/Release/GRBL-Plotter.exe`，未连接或控制机器。
