# 逐页换纸引导 — 使用与验证

## 做什么

多页写字不再靠来回切页猜“现在该写哪一页”。冻结之后，主界面底部和写字设置窗口同时显示：第几页/总页数，以及等待开始、书写中、暂停、等待换纸、全部完成、取消、异常或未知。

确认换纸只把下一页放进编辑器。仍要点主界面原来的开始。不会自动回零、不会自动走定位、不会自动开写。

## 怎么用

1. 从主界面 **AutoWriter → 机器配置与校准** 打开写字设置。
2. 排好两页以上的正文（普通分页或区域续页都可以）。
3. 点窗口下方 **冻结多页任务**。第 1 页载入主界面，状态为“等待开始”。
4. 换好纸、确认工作原点仍是这一页要用的原点，再点主界面原来的开始。
5. 状态会经过“发送中 / 已发送，等待应答 / 已应答，等待空闲”。只有全部应答、收尾抬笔、连接还在、并且控制器在最后一条应答之后进入 Idle，才变成“等待换纸”。进度 100% 或最后一个 `ok` 不会当成写完。
6. 换下一张纸，再点 **已换纸并确认位置**（主界面底部或设置窗口）。只载入下一页。然后再手动开始。
7. 最后一页同样走完空闲屏障后显示“全部完成”，不再出现换纸按钮。

暂停仍是暂停，不会进入换纸。停止、报警、断连、命令错误都不推进页码，也不显示完成。已经发出去但没法确认笔有没有走完时，状态是“未知”，需要人工处理，不能自动续写。

改文本、字号、间距、字体、纸张、区域、轴映射或工作原点后，冻结任务失效，旧页代码不能再发送。书写过程中改参数不会假装这一页已经写完。

重复点“冻结”或“已换纸并确认位置”不会把同一页再载入一次，也不会因此发送。

## 离线检查

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/test-page-task.ps1
```

状态机检查不连机器。界面按钮检查需要先构建，再把新的 `GRBL-Plotter.exe` 路径传给同一个脚本。

## 实机两页

用 `artifacts/page-task/Release/GRBL-Plotter.exe`（或更新的完整目录），不要拿旧阶段目录里的 EXE。至少准备两页短字。

| 步骤 | 预期 |
|---|---|
| 冻结后不点开始 | 只显示等待开始，机器不动 |
| 第 1 页正常写完 | 只进入等待换纸，不自动载入或发送第 2 页 |
| 写到一半暂停 | 仍是暂停，不出现等待换纸 |
| 停止、报警或拔线 | 取消或未知，页码停在当前页 |
| 未点换纸就点开始 | 被拒绝，第 2 页不会启动 |
| 换纸确认连点两次 | 第 2 页只载入一次，不发送 |
| 确认后手动开始第 2 页 | 写出第 2 页；最后显示全部完成 |
